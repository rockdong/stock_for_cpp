## 🎯 技术要点总结

### 单例模式正确使用

```cpp
// ❌ 错误：手动管理生命周期
Config* config = new Config();
delete config;

// ✅ 正确：获取引用，不干预生命周期
Config* config = &Config::getInstance();
config = nullptr;  // shutdown时只置空
```

**判断标准**: 
- 有私有构造/析构
- 有 getInstance() 静态方法
→ 是单例，不应 new/delete

### 前置声明 vs 完整定义

```cpp
// ✓ 前置声明可用：指针、引用
class Stock;
Stock* stock;
void foo(Stock& s);

// ✗ 前置声明不可用：容器、成员访问
std::vector<Stock> stocks;  // 需要完整定义
stock->price;               // 需要完整定义
```

**使用规则**:
- 指针/引用 → 前置声明足够
- 容器/成员访问 → 必须完整定义

### CMake 生成文件配置

```cmake
target_include_directories(target PRIVATE
    ${CMAKE_BINARY_DIR}  # 必须包含，用于 version.h 等生成文件
)
```

**原因**: CMake 生成的文件在 build 目录，不在源代码目录

## 💡 关键学习点

### 系统调试 vs 随机修复

**系统调试**（正确方法）:
- 15-30分钟修复
- 95% 首次修复成功率
- 不引入新问题

**随机修复**（错误方法）:
- 2-3小时反复尝试
- 40% 首次修复成功率
- 经常引入新问题

### 根本原因优先

**错误做法**: 看到错误就猜，改改试试看  
**正确做法**: 分析根本原因，对症下药

**案例**:
```
错误: calling a private constructor
猜测修复: 改为 public → 破坏单例设计 ✗
根本原因: Config 是单例，不应直接 new ✓
正确修复: 使用 getInstance() ✓
```

### 最小化修改原则

**禁止**:
- 不要"顺便重构"
- 不要"顺便优化"
- 不要一次改多处

**要求**:
- 只修复这一个特定问题
- 最小化修改范围
- 每次修复后验证
